## 3. 根因

### 3-1 手機載了 10.4 MB 的桌機影片

`HeroSection.tsx` 用 `isPortrait` 狀態決定播哪支影片：

```tsx
const [isPortrait, setIsPortrait] = useState(false);   // ← SSR 時必定是 false
useEffect(() => {
  const mql = window.matchMedia("(max-aspect-ratio: 1/1)");
  setIsPortrait(mql.matches);                          // ← 要等 hydration 之後
}, []);

const useSrc = isPortrait && slide.media.portraitSrc ? slide.media.portraitSrc : slide.media.src;
```

伺服器端算不出視窗方向，所以首次渲染一律用桌機影片，而 slide 0 帶著
`autoPlay` + `preload="auto"` → 瀏覽器立刻開始下載 23 MB 的 `hero-cai-mep-1080.mp4`。
hydration 之後 `useSrc` 改變、`key` 改變 → `<video>` 重新掛載換成直式影片。

在快網路 + 暖快取下，那個請求會來得及被取消（傳輸 0 bytes）；
**但在真實手機條件（冷快取、節流網路）下，它來得及載完 10.4 MB。**

> ⚠️ 這一條我（Claude）一度用「帶快取的本機瀏覽器測試」判定為「不成立」，是錯的。
> 教訓：**效能問題必須在冷快取 + 節流條件下量，暖快取的測試會得到相反結論。**

### 3-2 poster 圖原檔直出，且尺寸超規格 10 倍

三張 poster 是用 CSS `background-image` 塞的：

```tsx
<div className="absolute inset-0 bg-cover bg-center"
     style={{ backgroundImage: `url('${slide.media.poster}')` }} />
```

CSS 背景圖**完全繞過 Next.js 的圖片最佳化**（不會轉 WebP/AVIF、不會依裝置出圖），
等於把 4096×2160 的原始 JPG 直接丟給 390px 寬的手機。

## 4. 優化方案（按投報率排序）

### ① 手機不要載桌機影片 — 省 10.4 MB（佔問題的 69%）

可行做法（擇一，實作時再定）：
- 在 `isPortrait` 確定之前不要給 `src`（配合 `preload="none"`），方向確定後才設
- 或用原生 `<source media="(max-aspect-ratio: 1/1)">` 讓瀏覽器自己選（需先驗 Safari 支援度）

### ② poster 改 WebP 並依尺寸出圖 — 手機省 94%

實測轉檔結果（非估算，用 PIL `quality=78/72, method=6`）：

| poster | 原尺寸 | 現在 JPG | 手機（828 寬 WebP） | 桌機（1600 寬 WebP） |
|---|---|---|---|---|
| slide 1 貨櫃船 | 1920×1080 | 356 K | **54 K** | 161 K |
| slide 2 地圖 | 4096×2160 | 407 K | **14 K** | 41 K |
| slide 3 公路 | 4096×2160 | 938 K | **32 K** | 109 K |
| **合計** | | **1.66 MB** | **0.10 MB** | **0.31 MB** |

### ③ 字型 ~450 KB（效益最小，先不急）

六個 woff2 全載。Noto Sans TC 是中文字型本來就大，可砍掉沒用到的字重，
但**動字重有視覺風險**，要先盤點哪些字重真的有用到。

**①+② 做完，手機傳輸量預估從 15.08 MB 降到約 1.5 MB。**

## 5. 動工時必跑的驗收（不可省略）

這些改動會動到 hero 的載入行為，而 hero 剛修過三輪，所以要防回歸：

1. **重跑對比度 18 格**（桌機/手機/reduced-motion × 3 張 × 主標/副標/次CTA）
   → ⚠️ poster 是 `prefers-reduced-motion` 時的**永久背景**，重新編碼後必須重驗對比度
2. **重跑輪播播放斷言**：三張都要能播、任何時刻**只能有一支**在播、直跳第三格不能卡靜態圖
3. **像素比對** hero 在 1440×900 與 390×844 的前後差異
4. **重跑 Lighthouse** 前後對照（同樣參數）
5. 檢查 poster 在大面積平滑區域（貨櫃船的水面）有沒有色帶（banding）

## 6. 同時發現、尚未處理的問題

| # | 問題 | 影響 |
|---|---|---|
| 1 | 進度條動畫 `hero-progress` 是 **7000ms**，但 `AUTOPLAY_MS` 是 **10000** | 進度條跑滿後呆坐 3 秒；每個訪客都看得到 |
| 2 | `progressKey.current += 1` 寫在 render body 裡 | 任何 re-render 都會讓進度條動畫重跑 |
| 3 | `prefers-reduced-motion` 時影片其實還在播（CSS 只是 `display:none`） | 無障礙 + 白耗流量 |
| 4 | slide 2、3 沒有直式版本，手機照樣抓 1080p 橫式檔再裁成窄條 | 手機額外流量 |
